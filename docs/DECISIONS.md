# Decisions

Design decisions whose reasoning is longer than a code comment should carry. Each entry is referenced from the code it governs by its ID, so the comment states what breaks and the ledger holds why the fix is shaped the way it is. The format is set by `core/contracts/CODE_INTENT_STANDARD.md` §3.

Add an entry only when the reasoning outlives the code — a boundary that was measured, a rule that was tried and rejected, a failure that recurs if the constraint is dropped. Everything else belongs in the comment.

| ID | Decision |
| --- | --- |
| `FALSIFIABILITY-1` | Ten defects in this repo turned out to be one shape: a check that reported success it had not earned. None were sloppiness — each was scaffolding that stayed after real usage diverged — and none could be caught by reading the output, because the output always said PASS. `post-commit` printed "Verification: PASS" and always exited 0; Gate 4 announced "passed" over an empty pattern list; Gate 2 silently passed everything when perl was absent; `CRITICAL_ISSUES` was compared but never incremented, so its exit 2 was unreachable; `node --test *.mjs` exited 0 on zero matched files; QA sections 1 and 7 printed findings-shaped output and never incremented; `apply-token-policy` filtered nothing for an unknown repo and said nothing; `findings_documented` accepted `""` as a completed audit. The common property is unfalsifiability: no input could make them fail. `scripts/lib/falsifiability_check.py` looks for that property directly, so the class stops being rediscovered by hand. Its two detectors are deliberately precise rather than clever — a noisy meta-check gets ignored, which is the very failure it exists to prevent. |
| `GATE-COUNT-1` | Gate coverage is per-repo-type — 8 gates in OliverCode, 6 in a repo that adopts the framework, 2 in the vault's private variant — so a doc's gate-count claim is resolved to the hook it is about before being compared. Five tracked documents had stated 8 as though it were universal, telling forkers their repos would get contract integrity and token policy, two gates the template does not ship. The consistency checker was in place the whole time and passed for two independent reasons: it compared every claim against OliverCode's own hook and skipped `core/templates/` outright, so the discrepancy was known to it and deliberately unexamined; and its claim pattern required the number adjacent to the noun, so README's headline "8 pre-commit gates" was never matched at all. The template also disagreed with itself, its banners reading "Gate 1/5" through "Gate 5/5" and then "Gate 6/6", because nothing checked a hook other than OliverCode's. Pinned by `tests/test_gate_coverage.py`, where each test is a mutation that breaks one thing and asserts the checker fails. |
