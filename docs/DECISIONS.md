# Decisions

Design decisions whose reasoning is longer than a code comment should carry. Code may cite an entry by its ID, so the comment states what breaks and the ledger holds why the fix is shaped the way it is.

Add an entry only when the reasoning outlives the code — a boundary that was measured, a rule that was tried and rejected, a failure that recurs if the constraint is dropped. Everything else belongs in the comment.

| ID | Decision |
| --- | --- |
| `GATE-FALSIFIABILITY-1` | Ten defects in this repo turned out to be one shape: a check that reported success it had not earned. None were sloppiness — each was scaffolding that stayed after real usage diverged — and none could be caught by reading the output, because the output always said PASS. `post-commit` printed "Verification: PASS" and always exited 0. Gate 4 announced "passed" over an empty pattern list. Gate 2 silently passed everything when perl was absent. `CRITICAL_ISSUES` was compared but never incremented, so its exit 2 was unreachable. `node --test *.mjs` exited 0 on zero matched files. QA sections 1 and 7 printed findings-shaped output and never incremented. `apply-token-policy` filtered nothing for an unknown repo and said nothing. `findings_documented` accepted `""` as a completed audit. The common property is unfalsifiability: no input could make them fail. `scripts/lib/falsifiability_check.py` looks for that property directly, so the class stops being rediscovered by hand. Its two detectors are deliberately precise rather than clever — a noisy meta-check gets ignored, which is the very failure it exists to prevent. |
| `GATE-COUNT-1` | Gate coverage differs by repo type, and docs/GOVERNANCE.md's table is its single home, so every claim in a tracked doc resolves to the hook it is about before being compared. Five documents had stated OliverCode's own total as though it were universal, promising forkers contract integrity and token policy, neither of which the template ships. The checker was in place the whole time and passed for two independent reasons: it compared every claim against OliverCode's own hook and skipped `core/templates/` outright, so the discrepancy was known to it and deliberately unexamined. And its pattern required the numeral adjacent to the noun, so README's headline form was never matched at all. The template also disagreed with itself, its banners running to one total and then another, because nothing checked a hook other than OliverCode's. Pinned by `tests/test_gate_coverage.py`, where each test is a mutation that breaks one thing and asserts the checker fails. |
| `BACKLOG-HYGIENE-1` | The backlog policy ("finished items are removed rather than ticked") was instruction text only, and one fleet repo's `docs/BACKLOG.md` reached 15,058 lines across 50 dated sections before anyone noticed, most already shipped and marked so in the heading itself rather than removed. `check-backlog-hygiene.mjs` fails on a literal DONE marker in a heading rather than a line-count cap: a cap was tried first and rejected against the live fleet, because a different repo's backlog legitimately runs 500+ lines of real open work (Blocked / Features / Deprioritized, zero DONE headings) and would have failed a generic size limit the actual defect never touches. "not done" is excluded from the match — a heading announcing work is NOT finished is the opposite signal and an early version of the check flagged it as a false positive. |
| `COVERAGE-MAP-1` | `scripts/qa/check-code-quality.sh`'s Test Coverage Map only globbed `lib/*/` (one directory per module) — silently inert for this repo's own flat `scripts/lib/*.py` layout, so it always reported "All lib modules have test coverage" whether or not that was true, the exact `GATE-FALSIFIABILITY-1` shape. Found in a deep-review pass because it let a real gap through: `duplication_check.py` landed with zero tests and nothing caught it. Fixed by adding a parallel pass for the flat-file layout, matched by the literal `"scripts/lib/<module>.py"` string each test file's `importlib.util.spec_from_file_location` call uses to load its module — filename-substring matching was tried first and produced false positives, because tests here are named by behavior (`test_falsifiability.py`), not by the module filename (`falsifiability_check.py`). |
| `EARLY-STOP-1` | The third-party `fablize` plugin's `finish-the-work.sh` catches a turn that ends by promising work ("I'll implement this now") instead of doing it -- a real, narrow, verified effect (per fablize's own README) that OliverCode had no equivalent for, since the framework ships zero Claude-Code-level hooks, only git pre-commit hooks. `scripts/hooks/early-stop-guard.py` is OliverCode's own implementation of the same idea, written fresh (stdlib Python, this repo's own conventions), not vendored -- part of extracting fablize's two verified-real gaps before removing the plugin as a separate dependency. Same detection shape: regex over only the closing paragraph of the last assistant turn, skip if it ended with a tool call or a question to the user, fail open on anything unparseable. Tested against four fixture transcripts (promise/asks/tool-call/normal-completion) before trusting it -- the first test run silently passed all four, including the one that should have blocked, because the fixture path sat outside the hook's own TMPDIR/HOME safety check (macOS resolves `/tmp` to `/private/tmp`, not the real `$TMPDIR`); moving fixtures under `$HOME` reproduced the correct block/pass split on all four. |
| `BACKUP-COLLISION-1` | `olivercode install`'s `_link()` backed up a real-file collision to `<name>.pre-olivercode`, and a second collision to `<name>.pre-olivercode.bak` — but never checked whether `.bak` itself already existed before renaming into it. `Path.rename` overwrites its destination on POSIX, so a third collision at the same path silently destroyed the second backup, contradicting the function's own "never destructive" contract. Found in a deep-review pass, not live — no destroyed backup was observed, only the code path that would produce one. Fixed by counting suffixes (`.pre-olivercode.2`, `.3`, ...) until a free name is found instead of a fixed two-name fallback. |
| `GATE-DUPLICATION-1` | A full manual read of every tracked doc (2026-09-09) found the same rule restated near-verbatim in four separate places, in a repo that had already been through a dedicated dedup audit weeks earlier — the audit caught what existed at the time, but nothing mechanical watched for it regrowing. `scripts/lib/duplication_check.py` slides a 15-word window across every tracked markdown file and fails on any window shared by two files, unless the shared text matches a declared marker (the same shape as `hook_drift_check.py`'s `DECLARED_DIFFERENCES` — a reused canonical phrase or a deliberate skill-quotes-its-contract pattern, not drift). Exact-substring only, not semantic similarity, by design: a check should be precise rather than clever, or a noisy one gets ignored (`GATE-FALSIFIABILITY-1`'s own lesson). Live-run against this repo found three real, undeclared duplicates on first pass, each fixed in the same session — not hypothetical. |
| `STE-JOIN-1` | The vendor `ste-lint.py` (asd-ste100) splits sentences one physical line at a time. A paragraph hard-wrapped at ~95 characters never shows it a sentence longer than one line, so the 25-word long-sentence cap never fires on wrapped prose. Found 2026-09-25: a vault skill linted at 0 hard violations wrapped and 21 once its paragraphs were joined. Folded YAML `description: >` values hid long sentences the same way. The fix is `core/templates/project/ste-lint-joined.py`, which imports the vendor linter, joins soft-wrapped lines, and runs the vendor `main()`. It does not edit the vendor file: that file comes from `npx skills add` and a reinstall would silently undo the edit. Joined text lands on the block's first line and consumed lines go blank, so reported line numbers stay true to the real file. `sync-hooks` installs the wrapper beside each hook and `health` fails when it is missing or stale. The gate blocks rather than falling back to the raw linter, because a silent fallback is the bypass this entry exists to close. |
| `GATE-SCOPE-1` | `core/templates/project/pre-commit-private`'s Gate 4 matched only the two literal filenames `SKILL.md` and `CLAUDE.md`, by bare basename. A fleet repo's `references/*.md` file carried 17 real asd-ste100 violations the gate never saw, because a reference file is the exact same agent-parsed prose by a different name — the gate's own stated reason for existing (SKILLS-PLACEMENT.md's ACT-3) applies to it identically. Fixed by matching path shape (`*/SKILL.md`, `*/CLAUDE.md`, `*/references/*.md`) instead of bare filename. Ablated against a scratch repo: a long sentence planted in a staged `references/*.md` file blocked the commit, and passed once shortened. |
| `GATE-BASELINE-1` | `GATE-SCOPE-1` extended Gate 4 to `references/*.md`, and a real fleet repo's reference files carried over 150 pre-existing hard violations that gate had never checked — committing one unrelated line to any of them would have had to clear all of it first, the same "fails a thousand times on day one" shape `check-decisions.mjs`'s own adoption baseline already solves for decision records (that file's own docstring names the risk directly). `core/templates/project/write-ste-baseline.py` writes `.githooks/ste-baseline` (`path:count`, per repo, outside every template so `sync-hooks` never touches it — same placement as `ste-exemptions`): the real hard-violation count ste-lint.py's own native `--baseline N` flag (already built into the vendor linter, unused until now) accepts for that file. A file not listed keeps baseline 0, unchanged from before. Fixing some of a listed file's debt still passes; a genuinely new violation on top of the baseline still blocks, because the count then exceeds it. Ablated against a scratch repo: 2 pre-existing violations against baseline 2 passed, a 3rd new one on top blocked. |
| `GATE-CITATION-1` | A staged skill file can cite `#N` as if it names a real GitHub issue. Two commits did exactly this in one fleet repo and nothing caught it before the citation shipped — a dead reference a reader has no way to detect short of trying the link. `core/templates/project/pre-commit-private`'s Gate 4 now collects every `#N`-shaped citation in a staged `SKILL.md`/`CLAUDE.md`/`references/*.md` file (bounded to 1-5 digits, excluding a markdown anchor, an HTML entity, and a hex color, which share the `#digits` shape but never mean an issue) and checks membership against one `gh issue list --state all` call for the repo's own remote. Checked only when `gh` is installed and already authenticated; any missing tool, auth failure, or API error (including a rate limit — hit twice live in the same session this gate was built) skips the check silently rather than blocking a commit on infrastructure the content gate does not own. Fail-open by design: this gate's job is catching a wrong citation, not guaranteeing network access. Ablated against a scratch repo pointed at a real public remote: a fabricated 5-digit issue number blocked the commit, a real closed issue number passed it. |
| `GATE-LOCAL-1` | The vault needs blocking checks that no other private repo has (fleet history language, dangling references, orphans). Putting them in `pre-commit-private` would ship vault-only logic to every private repo. Editing the deployed `pre-commit` in the vault would be overwritten by the next `sync-hooks`. The private hook runs a `pre-commit.local` file beside the hook when it exists and is executable, passes it the staged file list on stdin, and blocks the commit on a non-zero exit. `sync-hooks` never touches that file. |
| `D2` | The framework carries no repo-specific enforcement. `validate.sh --target-repo <root>` runs the target's own `scripts/validate-repo.sh` when it exists and skips cleanly when it does not. A profile may still carry `"suites"`, but nothing reads it: the only resolver for it served a subsystem that was removed, survived orphaned and tested only by itself, and was deleted. If delegated suites are ever built, they resolve through that flag and never through a hardcoded repo name. |
| `ACT-3` | A generic skill and a repo-specific approval-gated skill can match the same task, and nothing biases selection toward the gated one before a repo file is touched. The mechanism has no fix. The mitigation is a named, explicit directive in the repo's own `CLAUDE.md`, which `docs/SKILLS-PLACEMENT.md` describes. |
| `REGISTRY-PRIVATE-1` | The fleet registry names the operator's repos, waivers and services, so a fork must not inherit it. The real file lives in a private repo at `olivercode/repo-profiles.json`, found through `privateRepos` in `olivercode.local.json`. The tracked `shared/repo-profiles.json` ships as an empty example, and it is where a fork registers its own repos. An earlier design tracked the real registry directly, which published the operator's fleet to every clone. |
| `REFERENCE-INTEGRITY-1` | `scripts/link-check.sh` once saw only markdown links, while the real cross-references were backtick-quoted repo paths, and every stale path an audit found lived in that blind spot. `scripts/lib/reference_check.py` resolves backtick paths whose first segment is a tracked top-level directory, or which start with `$OC/`. Its exemptions are explicit: downstream-relative contract paths, gitignored runtime layers, placeholder tokens and the anti-pattern examples in `FILE_LOCATION_STANDARD.md`, whose paths must not resolve. |
| `SKILLS-INDEX-1` | `skills/INDEX.md` and the `skills/*/SKILL.md` folders drifted apart silently, because the launcher lists skills by frontmatter while people read the table. `scripts/lib/consistency_check.py` checks the table against the folders in both directions, and each frontmatter `name:` against its folder name. It shares one checker with the gate-count claims (`GATE-COUNT-1`), because both are the same failure: a document asserting what the code contradicts. |
| `CI-STRICT-1` | CI fails the build on `check-bloat.sh --strict`. `full-qa-pass.sh` stays advisory, because its other phases are heuristic and would block good commits. |
| `VOICE-COPIES-1` | The voice has one home, `docs/VOICE.md`, and a byte-identical copy in each self-contained suite. `ecommerce-system` and `automated-content-flow` ship their own `docs/VOICE.md` so they run without OliverCode, and `olivercode health` fails when a copy drifts. `CLAUDE.md` imports the fixed path `~/.claude/VOICE.md` because a relative import from the symlinked `~/.claude/CLAUDE.md` has no documented base directory. |
| `KEEPALIVE-SCOPE-1` | The keepalive surface is in scope by the owner's decision. It syncs through the bootstrap manifest's `conditionalFiles`, so it is not an orphan. |
| `EVIDENCE-OPT-IN-1` | The WRITE MODE evidence gate is opt-in. The machinery works and is tested, but no evidence record has ever existed in this fleet and every commit predates one. A contract that every commit violates teaches that written rules are optional, so `EXECUTION_CONTRACT.md` describes the gate as opt-in. |
| `ADD-REPO-WONTFIX-1` | Registering a repo means editing `repo-profiles.json` once. An `olivercode add-repo` command would cost a script, tests and docs to save a one-time edit, and it meets none of `FRAMEWORK_BASELINE.md`'s admission criteria. The real problem was Gate 8 failing with a message nobody could act on, and that is fixed. Revisit only if the fleet grows enough to make the edit repetitive. |
| `GOVERNANCE-CI-1` | The governance CI path (`scripts/run-governance-target.sh` and `core/templates/project/.github/workflows/olivercode-governance.yml`) is absent from every fleet repo while CI billing is paused. It works the moment CI returns, so it stays. |
