# Decisions

Design decisions whose reasoning is longer than a code comment should carry. Code may cite an entry by its ID, so the comment states what breaks and the ledger holds why the fix is shaped the way it is.

Add an entry only when the reasoning outlives the code — a boundary that was measured, a rule that was tried and rejected, a failure that recurs if the constraint is dropped. Everything else belongs in the comment.

| ID | Decision |
| --- | --- |
| `GATE-FALSIFIABILITY-1` | Ten defects shared one shape: a check that reported success it had not earned, so reading the output never exposed them. `post-commit` always exited 0, Gate 4 announced "passed" over an empty pattern list, `node --test *.mjs` exited 0 on zero matched files and `findings_documented` accepted `""`. `scripts/lib/falsifiability_check.py` looks for the property directly, a check that no input can fail. Its two detectors are deliberately precise, because a noisy meta-check gets ignored. Pinned by `tests/test_falsifiability.py`. |
| `COVERAGE-MAP-1` | The coverage map in `scripts/validate.sh` (`run_code_quality`) globbed only `lib/*/`, which matches nothing in this repo's flat `scripts/lib/*.py` layout, so it always reported full coverage (the `GATE-FALSIFIABILITY-1` shape) and let `duplication_check.py` land with no tests. It now looks for each `scripts/lib` module's name in the test files, because tests are named by behavior (`test_falsifiability.py` covers `falsifiability_check.py`). |
| `EARLY-STOP-1` | A turn that ends by promising work ("I'll implement this now") and never does it needs a guard, and the framework shipped no Claude Code hooks to catch it. `scripts/hooks/early-stop-guard.py` matches a regex against the closing paragraph of the last assistant turn, skips a turn that ended with a tool call or a question, and fails open on anything unparseable. The first test run passed all four fixture transcripts, including the one that should block, because the fixtures sat outside the hook's TMPDIR/HOME safety check (macOS resolves `/tmp` to `/private/tmp`). Fixtures under `$HOME` give the correct split. `docs/RULES.md` ("Execution") lists the hooks. |
| `BACKUP-COLLISION-1` | `install` backed up a collision to `<name>.pre-olivercode` and a second to `.pre-olivercode.bak` without checking that `.bak` was free. `Path.rename` overwrites on POSIX, so a third collision would destroy the second backup and break the "never destructive" contract. Found in review and never observed. It now counts suffixes (`.2`, `.3`) until a name is free. |
| `GATE-DUPLICATION-1` | A manual read of every tracked doc found one rule restated near-verbatim in four places, and nothing mechanical watched for regrowth. `scripts/lib/duplication_check.py` slides a 15-word window across tracked markdown and fails on any window two files share, unless it matches a declared marker. It matches exact substrings by design, because a noisy check gets ignored (`GATE-FALSIFIABILITY-1`). Its first run found three real duplicates, fixed the same session. |
| `GATE-SCOPE-1` | The skill-citation gate matched only the two literal filenames `SKILL.md` and `CLAUDE.md`, by bare basename, so a fleet repo's `references/*.md` file with a dead issue citation went unchecked. A reference file is the same agent-read text under another name. The gate now matches path shape (`*/SKILL.md`, `*/CLAUDE.md`, `*/references/*.md`). It blocks on a fabricated issue citation (`GATE-CITATION-1`). |
| `GATE-CITATION-1` | A staged skill file can cite `#N` as if it were a real GitHub issue, and two commits did so unnoticed. Gate 4 of `core/templates/project/pre-commit-private` collects each `#N` citation (1 to 5 digits, excluding anchors, HTML entities and hex colors) in a staged `SKILL.md`, `CLAUDE.md` or `references/*.md` and checks it against one `gh issue list --state all` call. It runs only where `gh` is installed and authenticated and skips silently on any error, including a rate limit, because the gate owns the content check, and the network belongs to `gh`. Ablation: a fabricated 5-digit number blocked a commit and a real closed issue passed. |
| `GATE-LOCAL-1` | A private repo can need blocking checks that no other private repo has, and `sync-hooks` overwrites an edited deployed hook. The private hook therefore runs an executable `pre-commit.local` beside it, passes the staged file list on stdin and blocks on a non-zero exit. `sync-hooks` never touches that file. The archived-content gate asks it `archive-exempt <path>` before blocking, and exit status 10 exempts the path, so the framework holds no repo-specific exemption. |
| `HOOK-OUTPUTS-1` | The committed `core/templates/project/pre-commit` and `core/templates/project/pre-commit-private` are build outputs of `scripts/build-hooks.py`, kept in the repo because `sync-hooks` and bootstrap copy them byte for byte into other repos, and a fresh checkout has to work before anything runs a build. Story #43 said they are generated at run time, and this entry amends that wording. `validate.sh` runs `build-hooks.py --check`, so a hand edit or a stale build fails, and the fix is always an edit under `core/hooks/` followed by a rebuild. |
| `ACT-3` | A generic skill and a repo-specific approval-gated skill can match the same task, and nothing biases selection toward the gated one before a repo file is touched. The mechanism has no fix. The mitigation is a named, explicit directive in the repo's own `CLAUDE.md`, which `docs/RULES.md` ("Skill placement") describes. |
| `REGISTRY-PRIVATE-1` | The fleet registry names the operator's repos and services, so a fork must not inherit it. The real file lives in a private repo at `olivercode/repo-profiles.json`, found through `privateRepos` in `olivercode.local.json`. The tracked `shared/repo-profiles.json` ships as an empty example, and it is where a fork registers its own repos. An earlier design tracked the real registry directly, which published the operator's fleet to every clone. |
| `REFERENCE-INTEGRITY-1` | `scripts/link-check.sh` once saw only markdown links, while the real cross-references were backtick-quoted repo paths, and every stale path an audit found lived in that blind spot. `scripts/lib/reference_check.py` resolves backtick paths whose first segment is a tracked top-level directory, or which start with `$OC/`. Its exemptions are explicit: downstream-relative contract paths, gitignored runtime layers, placeholder tokens and the anti-pattern examples in `docs/RULES.md` ("File locations"), which are written without backticks so no path in them is checked. |
| `SKILLS-INDEX-1` | `skills/INDEX.md` and the `skills/*/SKILL.md` folders drifted apart silently, because the launcher lists skills by frontmatter while people read the table. `scripts/lib/consistency_check.py` checks the table against the folders in both directions, and each frontmatter `name:` against its folder name. |
| `CI-STRICT-1` | `validate.sh` fails on tracked archive-style directories and on files that mark themselves historical, and CI runs it. The docs-to-code ratio only warns, because it is a heuristic that would block good commits. |
| `VOICE-COPIES-1` | The voice has one home, `docs/VOICE.md`, and a byte-identical copy in each self-contained suite. Each self-contained suite ships its own `docs/VOICE.md` so they run without OliverCode, and `olivercode health` fails when a copy drifts. `CLAUDE.md` imports the fixed path `~/.claude/VOICE.md` because a relative import from the symlinked `~/.claude/CLAUDE.md` has no documented base directory. |
| `ADD-REPO-WONTFIX-1` | Registering a repo means editing `repo-profiles.json` once. An `olivercode add-repo` command would cost a script, tests and docs to save a one-time edit, and it meets none of the admission criteria in `docs/RULES.md` ("Framework baseline"). The real problem was Gate 8 failing with a message nobody could act on, and that is fixed. Revisit only if the fleet grows enough to make the edit repetitive. |
| `DOCS-ONE-HOME-1` | Documents answered overlapping questions, so a new user met the same install steps in several places and stale claims survived in the copies nobody opened. Each question now has one home: `README.md` for what OliverCode is, `docs/SETUP.md` for installing, restoring, commands and troubleshooting, `docs/RULES.md` for standing rules, `docs/GATES.md` for gates, plus `CLAUDE.md`, `docs/VOICE.md`, this file and `docs/BACKLOG.md`. `scripts/lib/duplication_check.py` and `scripts/link-check.sh` keep the split from regrowing. |
| `HOOK-DISTRIBUTION-1` | `olivercode sync-hooks` stays as the way gates reach repos. The pre-commit framework, lefthook and Husky each need an install per clone, a global `core.hooksPath` has no per-repo layer, and none checks that a hook is installed and running, which `hook_problems` and `gate_problem` in `scripts/lib/repo_gates.py` exist to catch. A switch would remove about 330 lines and lose that check. Revisit if collaborators start cloning fleet repos routinely, the fleet outgrows one machine, or one of these tools documents an installed-hook check. |
| `GATE-PRUNE-1` | Deleted repo refs, contract integrity and backlog hygiene were removed because none could name a defect it still prevents: its pattern list shipped empty, it read a folder that no longer exists, or it guarded a file-based backlog that moved to GitHub issues. Planning doc governance followed, since only two repos carry its checker. The other gates stayed because each blocks a named defect and can fire. `docs/GATES.md` holds the verdicts and the counts. |
| `SIZE-RAISE-1` | The size ratchet trusted a baseline edited in the same commit, so three stories of one epic raised the total from 18,293 to 19,581 lines inside the headroom without a check. A pre-commit gate cannot read the commit message and the commit-msg hook can, so the commit-msg hook caps a raise at `raiseCapPercent` of the committed baseline and requires a `Size: L` or `Size: XL` line above it. Pinned by `TestRaiseCap` in `tests/test_size_command.py`. |
