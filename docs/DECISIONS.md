# Decisions

Design decisions whose reasoning is longer than a code comment should carry. Code may cite an entry by its ID, so the comment states what breaks and the ledger holds why the fix is shaped the way it is.

Add an entry only when the reasoning outlives the code — a boundary that was measured, a rule that was tried and rejected, a failure that recurs if the constraint is dropped. Everything else belongs in the comment.

| ID | Decision |
| --- | --- |
| `GATE-FALSIFIABILITY-1` | Ten defects in this repo turned out to be one shape: a check that reported success it had not earned. None were sloppiness — each was scaffolding that stayed after real usage diverged — and none could be caught by reading the output, because the output always said PASS. `post-commit` printed "Verification: PASS" and always exited 0. Gate 4 announced "passed" over an empty pattern list. Gate 2 silently passed everything when perl was absent. `CRITICAL_ISSUES` was compared but never incremented, so its exit 2 was unreachable. `node --test *.mjs` exited 0 on zero matched files. QA sections 1 and 7 printed findings-shaped output and never incremented. `apply-token-policy` filtered nothing for an unknown repo and said nothing. `findings_documented` accepted `""` as a completed audit. The common property is unfalsifiability: no input could make them fail. `scripts/lib/falsifiability_check.py` looks for that property directly, so the class stops being rediscovered by hand. Its two detectors are deliberately precise rather than clever — a noisy meta-check gets ignored, which is the very failure it exists to prevent. |
| `GATE-COUNT-1` | Gate coverage differs by repo type, and docs/GATES.md's table is its single home, so every claim in a tracked doc resolves to the hook it is about before being compared. Five documents had stated OliverCode's own total as though it were universal, promising forkers the contract-integrity gate, which the template does not ship. The checker was in place the whole time and passed for two independent reasons: it compared every claim against OliverCode's own hook and skipped `core/templates/` outright, so the discrepancy was known to it and deliberately unexamined. And its pattern required the numeral adjacent to the noun, so README's headline form was never matched at all. The template also disagreed with itself, its banners running to one total and then another, because nothing checked a hook other than OliverCode's. Pinned by `tests/test_gate_coverage.py`, where each test is a mutation that breaks one thing and asserts the checker fails. |
| `BACKLOG-HYGIENE-1` | The backlog policy ("finished items are removed rather than ticked") was instruction text only, and one fleet repo's `docs/BACKLOG.md` reached 15,058 lines across 50 dated sections before anyone noticed, most already shipped and marked so in the heading itself rather than removed. `check-backlog-hygiene.mjs` fails on a literal DONE marker in a heading rather than a line-count cap: a cap was tried first and rejected against the live fleet, because a different repo's backlog legitimately runs 500+ lines of real open work (Blocked / Features / Deprioritized, zero DONE headings) and would have failed a generic size limit the actual defect never touches. "not done" is excluded from the match — a heading announcing work is NOT finished is the opposite signal and an early version of the check flagged it as a false positive. |
| `COVERAGE-MAP-1` | The test coverage map in `scripts/validate.sh` (`run_code_quality`) once only globbed `lib/*/` (one directory per module) — silently inert for this repo's own flat `scripts/lib/*.py` layout, so it always reported full coverage whether or not that was true, the exact `GATE-FALSIFIABILITY-1` shape. It let a real gap through: `duplication_check.py` landed with zero tests and nothing caught it. The check now looks for each `scripts/lib` module's name in the test files, because tests here are named by behavior (`test_falsifiability.py`), and the module filename (`falsifiability_check.py`) does not appear in the test's own name. |
| `EARLY-STOP-1` | The third-party `fablize` plugin's `finish-the-work.sh` catches a turn that ends by promising work ("I'll implement this now") instead of doing it -- a real, narrow, verified effect (per fablize's own README) that OliverCode had no equivalent for, since the framework then shipped no Claude Code hooks, only git pre-commit hooks. It now ships three, which `docs/RULES.md` ("Execution") lists. `scripts/hooks/early-stop-guard.py` is OliverCode's own implementation of the same idea, written fresh (stdlib Python, this repo's own conventions), not vendored -- part of extracting fablize's two verified-real gaps before removing the plugin as a separate dependency. Same detection shape: regex over only the closing paragraph of the last assistant turn, skip if it ended with a tool call or a question to the user, fail open on anything unparseable. Tested against four fixture transcripts (promise/asks/tool-call/normal-completion) before trusting it -- the first test run silently passed all four, including the one that should have blocked, because the fixture path sat outside the hook's own TMPDIR/HOME safety check (macOS resolves `/tmp` to `/private/tmp`, not the real `$TMPDIR`); moving fixtures under `$HOME` reproduced the correct block/pass split on all four. |
| `BACKUP-COLLISION-1` | `olivercode install`'s `_link()` backed up a real-file collision to `<name>.pre-olivercode`, and a second collision to `<name>.pre-olivercode.bak` — but never checked whether `.bak` itself already existed before renaming into it. `Path.rename` overwrites its destination on POSIX, so a third collision at the same path silently destroyed the second backup, contradicting the function's own "never destructive" contract. Found in a deep-review pass, not live — no destroyed backup was observed, only the code path that would produce one. Fixed by counting suffixes (`.pre-olivercode.2`, `.3`, ...) until a free name is found instead of a fixed two-name fallback. |
| `GATE-DUPLICATION-1` | A full manual read of every tracked doc (2026-09-09) found the same rule restated near-verbatim in four separate places, in a repo that had already been through a dedicated dedup audit weeks earlier — the audit caught what existed at the time, but nothing mechanical watched for it regrowing. `scripts/lib/duplication_check.py` slides a 15-word window across every tracked markdown file and fails on any window shared by two files, unless the shared text matches a declared marker (a reused canonical phrase or a deliberate skill-quotes-its-contract pattern, not drift). Exact-substring only, not semantic similarity, by design: a check should be precise rather than clever, or a noisy one gets ignored (`GATE-FALSIFIABILITY-1`'s own lesson). Live-run against this repo found three real, undeclared duplicates on first pass, each fixed in the same session — not hypothetical. |
| `GATE-SCOPE-1` | The skill-citation gate matched only the two literal filenames `SKILL.md` and `CLAUDE.md`, by bare basename, so a fleet repo's `references/*.md` file with a dead issue citation went unchecked. A reference file is the same agent-read text under another name. The gate now matches path shape (`*/SKILL.md`, `*/CLAUDE.md`, `*/references/*.md`). It blocks on a fabricated issue citation (`GATE-CITATION-1`). |
| `GATE-CITATION-1` | A staged skill file can cite `#N` as if it names a real GitHub issue. Two commits did exactly this in one fleet repo and nothing caught it before the citation shipped — a dead reference a reader has no way to detect short of trying the link. `core/templates/project/pre-commit-private`'s Gate 4 now collects every `#N`-shaped citation in a staged `SKILL.md`/`CLAUDE.md`/`references/*.md` file (bounded to 1-5 digits, excluding a markdown anchor, an HTML entity, and a hex color, which share the `#digits` shape but never mean an issue) and checks membership against one `gh issue list --state all` call for the repo's own remote. Checked only when `gh` is installed and already authenticated; any missing tool, auth failure, or API error (including a rate limit — hit twice live in the same session this gate was built) skips the check silently rather than blocking a commit on infrastructure the content gate does not own. Fail-open by design: this gate's job is catching a wrong citation, not guaranteeing network access. Ablated against a scratch repo pointed at a real public remote: a fabricated 5-digit issue number blocked the commit, a real closed issue number passed it. |
| `GATE-LOCAL-1` | A private repo can need blocking checks that no other private repo has, such as history-language checks, dangling references or orphans. Putting them in `pre-commit-private` would ship one repo's logic to every private repo, and editing the deployed `pre-commit` would be overwritten by the next `sync-hooks`. The private hook runs a `pre-commit.local` file beside the hook when it exists and is executable, passes it the staged file list on stdin, and blocks the commit on a non-zero exit. `sync-hooks` never touches that file. The archived-content gate in every variant also asks it about a path before blocking, by running `pre-commit.local archive-exempt <path>`, and exit status 10 exempts the path. The framework therefore carries no repo-specific archive exemption, and a repo with permanent records in an archive-named folder declares them in its own `pre-commit.local`. |
| `HOOK-OUTPUTS-1` | The committed `core/templates/project/pre-commit` and `core/templates/project/pre-commit-private` are build outputs of `scripts/build-hooks.py`, kept in the repo because `sync-hooks` and bootstrap copy them byte for byte into other repos, and a fresh checkout has to work before anything runs a build. Story #43 said they are generated at run time, and this entry amends that wording. `validate.sh` runs `build-hooks.py --check`, so a hand edit or a stale build fails, and the fix is always an edit under `core/hooks/` followed by a rebuild. |
| `D2` | The framework carries no repo-specific enforcement. `validate.sh --target-repo <root>` runs the target's own `scripts/validate-repo.sh` when it exists and skips cleanly when it does not. A profile may still carry `"suites"`, but nothing reads it: the only resolver for it served a subsystem that was removed, survived orphaned and tested only by itself, and was deleted. If delegated suites are ever built, they resolve through that flag and never through a hardcoded repo name. |
| `ACT-3` | A generic skill and a repo-specific approval-gated skill can match the same task, and nothing biases selection toward the gated one before a repo file is touched. The mechanism has no fix. The mitigation is a named, explicit directive in the repo's own `CLAUDE.md`, which `docs/RULES.md` ("Skill placement") describes. |
| `REGISTRY-PRIVATE-1` | The fleet registry names the operator's repos, waivers and services, so a fork must not inherit it. The real file lives in a private repo at `olivercode/repo-profiles.json`, found through `privateRepos` in `olivercode.local.json`. The tracked `shared/repo-profiles.json` ships as an empty example, and it is where a fork registers its own repos. An earlier design tracked the real registry directly, which published the operator's fleet to every clone. |
| `REFERENCE-INTEGRITY-1` | `scripts/link-check.sh` once saw only markdown links, while the real cross-references were backtick-quoted repo paths, and every stale path an audit found lived in that blind spot. `scripts/lib/reference_check.py` resolves backtick paths whose first segment is a tracked top-level directory, or which start with `$OC/`. Its exemptions are explicit: downstream-relative contract paths, gitignored runtime layers, placeholder tokens and the anti-pattern examples in `docs/RULES.md` ("File locations"), which are written without backticks so no path in them is checked. |
| `SKILLS-INDEX-1` | `skills/INDEX.md` and the `skills/*/SKILL.md` folders drifted apart silently, because the launcher lists skills by frontmatter while people read the table. `scripts/lib/consistency_check.py` checks the table against the folders in both directions, and each frontmatter `name:` against its folder name. It shares one checker with the gate-count claims (`GATE-COUNT-1`), because both are the same failure: a document asserting what the code contradicts. |
| `CI-STRICT-1` | `validate.sh` fails on tracked archive-style directories and on files that mark themselves historical, and CI runs it. The docs-to-code ratio only warns, because it is a heuristic that would block good commits. |
| `VOICE-COPIES-1` | The voice has one home, `docs/VOICE.md`, and a byte-identical copy in each self-contained suite. Each self-contained suite ships its own `docs/VOICE.md` so they run without OliverCode, and `olivercode health` fails when a copy drifts. `CLAUDE.md` imports the fixed path `~/.claude/VOICE.md` because a relative import from the symlinked `~/.claude/CLAUDE.md` has no documented base directory. |
| `EVIDENCE-OPT-IN-1` | The WRITE MODE evidence gate is opt-in. The machinery works and is tested, but no evidence record has ever existed in this fleet and every commit predates one. A contract that every commit violates teaches that written rules are optional, so `docs/RULES.md` ("Execution") describes the gate as opt-in. |
| `ADD-REPO-WONTFIX-1` | Registering a repo means editing `repo-profiles.json` once. An `olivercode add-repo` command would cost a script, tests and docs to save a one-time edit, and it meets none of the admission criteria in `docs/RULES.md` ("Framework baseline"). The real problem was Gate 8 failing with a message nobody could act on, and that is fixed. Revisit only if the fleet grows enough to make the edit repetitive. |
| `GOVERNANCE-CI-1` | The governance CI path (`scripts/run-governance-target.sh` and `core/templates/project/.github/workflows/olivercode-governance.yml`) is absent from every fleet repo while CI billing is paused. It works the moment CI returns, so it stays. |
| `DOCS-ONE-HOME-1` | Reader-facing documents answered overlapping questions. A new user met the same install steps in several places, and stale claims survived in the copies nobody opened: a README rehearsal described as a fake password when the probe writes a fake API key, "all three must pass" under four commands, citations of decision IDs that did not exist, and a ledger that was never written. Each question now has one document: `README.md` for what OliverCode is and how it fits together, `docs/SETUP.md` for installing, restoring, commands and troubleshooting, `docs/RULES.md` for every standing rule, `docs/GATES.md` for every gate, plus `CLAUDE.md`, `docs/VOICE.md`, this file and `docs/BACKLOG.md`. The standards that used to sit in a contracts folder moved into `docs/RULES.md`, and every script, hook message and template that named them by path moved with the merge. `scripts/lib/duplication_check.py` and `scripts/link-check.sh` keep the split from regrowing. |
| `HOOK-DISTRIBUTION-1` | `olivercode sync-hooks` stays as the way gates reach repos. The decision compares it with the pre-commit framework, lefthook, Husky and a global `core.hooksPath`, using each tool's documentation. **Install effort:** sync-hooks is one command for the whole fleet (`scripts/olivercode`, line 1010). The pre-commit framework needs the tool on every machine and `pre-commit install` in every clone, because the hook scripts are not shared through the repository (https://pre-commit.com/). Lefthook needs `lefthook install` and a package-manager or system install (https://lefthook.dev/). Husky needs a Node project with a `prepare` script (https://typicode.github.io/husky/how-to.html). **Updates:** sync-hooks copies the built hooks byte for byte, and `olivercode update` runs it. The pre-commit framework pins a `rev` per hook repo and moves it with `pre-commit autoupdate` in each repo (https://pre-commit.com/). Lefthook pulls shared config from a `remotes` entry pinned by `ref` (https://lefthook.dev/configuration/remotes/). A global `core.hooksPath` updates every repo at once, because Git reads hooks from that one directory instead of `$GIT_DIR/hooks` (https://git-scm.com/docs/git-config). **Per-repo overrides:** sync-hooks keeps `pre-commit.local` (`core/hooks/gates/repo-local.sh`, line 1) and a declared `hookVariant` (`scripts/olivercode`, line 1028). The pre-commit framework offers `repo: local` hooks and lefthook offers `lefthook-local.yml`, which merges last (https://lefthook.dev/configuration/remotes/). A global `core.hooksPath` has no per-repo layer, and a repo that sets its own path replaces it. **Collaborators:** none of the options is automatic. The framework and lefthook need an install per clone, and `pre-commit init-templatedir` covers newly cloned repos on one machine (https://pre-commit.com/#pre-commit-init-templatedir). sync-hooks has the same gap for a clone made elsewhere, which `docs/SETUP.md`, line 359, describes. **What a switch loses:** the health check that finds a silent `core.hooksPath` failure (`scripts/olivercode`, line 882, and `scripts/lib/repo_gates.py`) has no equivalent in any tool, since the documentation of all four describes no check for a missing install, and Git ignores hooks without the executable bit (https://git-scm.com/docs/githooks). The fail-closed secret gate and the story-reference gate are shell scripts assembled into one file per variant by `scripts/build-hooks.py`. The pre-commit framework would run them only as `repo: local` hooks with `language: unsupported_script` (https://pre-commit.com/), so the build stays and only the install path moves. **Size of a switch:** about 215 lines leave `scripts/olivercode` (`_hook_problems` 794-828, `_check_fleet_hooks` 882-962, the install and sync functions 966-1058, and the dispatch at 1234-1237), plus 189 lines of `tests/test_hook_install_health.py`, so roughly 400 lines. The gate scripts in `core/hooks/` (about 600 lines), `scripts/build-hooks.py` (133 lines) and the Claude Code commit guard stay, and a switch adds a config file and a hook repo to maintain per fleet repo. The count comes from `wc -l` on those ranges. **Decision:** the saving is small and the loss is the one check that exists to catch the failure this fleet has had, so the evidence does not favor a switch. Revisit if collaborators start cloning fleet repos routinely, if the fleet outgrows one operator's machine, or if one of these tools documents a check that a hook is installed and running. A switch would need its own story, with these steps: pin the gate scripts in a hook repo, add `.pre-commit-config.yaml` to each fleet repo, run `pre-commit install --hook-type pre-commit --hook-type commit-msg --hook-type pre-push` on each machine, rebuild the health check around `.git/hooks`, then delete the sync-hooks code above. |
