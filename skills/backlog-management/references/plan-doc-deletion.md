# Why a filed plan doc gets deleted

Precedent: `Delete SPEC-90's plan file, content already in Issue #93`. That deletion happened
once, ad hoc, before the deletion rule in `SKILL.md` step 6 existed. The same day the rule
got written, 19 other closed-work plan docs still sat in one repo's plans folder. The practice
was not consistent until the rule made it a required step, not a judgment call.

A plan file left next to its own filed issues is a duplicate a no-duplication repo shouldn't
keep. The same reasoning (the "why," evidence, tradeoffs) sitting in two places drifts when
one gets updated and the other doesn't.
