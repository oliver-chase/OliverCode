# To done

On "audit and fix" or `auditMode` full, the whole-target route continues past the report until the target is done, and the owner hears once when it is. Done means nothing is left: every finding is fixed at any priority, a fresh pass finds nothing at P2 or above, and the board holds no open issue except an owner action labeled `owner-action` or an item labeled `program`. A reopened audit continues from its ledger and its open items, and does not start over.

0. **Gate.** The audit runs unattended to the filed report. Then run `python3 scripts/audit_mode.py next` (add `--report-only` for a report-only request, `--fix` when the owner said "audit and fix") and follow its `action:`. `skip` ends the audit at the report and the filed issues, which is the default when `auditMode` is unset. `approve` shows the report, the issues filed and their priority order, asks once for approval and starts step 1 on a yes. `run` starts step 1 with no prompt. Print its `reminder:` line with the report. Both modes end with a final report of the fixes made, the story numbers, what was done and what is open
1. **Order.** P0 stories first, then deletions, then merges and fixes, then documentation, then text trims, then tests and voice. Deletions land before the docs and voice work that would rewrite the same text
2. **One story at a time.** Re-check the story against the live files, since another session may have changed them. Fix it, run the repo's validation and the story's before and after command, commit, push and merge as the repo's `CLAUDE.md` says, and close the story with the evidence. One commit never mixes stories
3. **Decisions.** Ask the owner whenever a decision or answer is not certain, and never guess. Put every open question in one message, each with a recommendation, then keep working on everything else. Record each answer on its story. `<target>/docs/AUDIT-ACCEPTED.md` holds only what cannot change, such as git history, and fixes the owner rejected, each with its reason. Nothing is deferred to a later epic to reach done
4. **Record the sharing verdict.** Write `Sharing: portable` or `Sharing: personal - reason` in the README or `<target>/docs/SHARING.md` from lens 10, and file a story for every blocker the verdict leaves
5. **Audit again.** When every story is closed, run steps 1 to 4 of the procedure with fresh readers who are not shown the earlier findings. Read the files the ledger lists as pending, and run the sweep and portability scripts on everything. File, fix and repeat until a pass finds nothing at P2 or above, then fix the cosmetic items that pass listed before closing. A third pass that still finds a P0 or P1 goes to the owner with the list
6. **Check.** `python3 "$OC/skills/audit/scripts/done_check.py" <repo> --epic <N>` (repeat `--epic` for each epic) must print `done`: the validation passes, no test file fails, the sweep is clean, the sharing verdict is recorded with no blocker it counts, the epic and its stories are closed, no issue is open except one labeled `owner-action` with its steps in the body and any labeled `program` (a fleet program tracked on its own epic, which the check lists by number and skips), and the backlog skill's board hygiene check is clean. Every other open issue is done and closed with evidence first
7. **Tell the owner once.** Give the numbers (files, lines, skill words, always-loaded tokens, tests, test time), the sharing verdict with its reason, every accepted row and every owner action with its steps. Offer a daily scheduled done check that notifies the owner the first time it stops printing `done`
